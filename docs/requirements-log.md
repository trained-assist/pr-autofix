## Отклонено (с причиной)

| # | Требование / ожидание | Почему отклонено |
|---|---|---|
| X-01 | «Наличие полей лог-контракта достаточно для AC-44» | Поля были на месте, значения — пустые. Требование переформулировано: receipt несёт фактические `sha` / `attempt` / `patch` / `path` / `budget`, а no-change не содержит патча. Проверяется поведением (`repro-r6-receipt.mjs`), не чтением схемы |
| X-02 | «Зелёный скрипт-регрессия = закрытое замечание ревью» | Регрессия R6 существовала и проходила локально, но была **не подключена ни к одному джобу**. Правило: у каждой регрессии своё имя в `ci.yml`; тест, не подключённый к джобу, не доказывает ничего |
| X-03 | «Чинить на стороне потребителя» (обход вместо правки движка) | Запрещено по плану: потребитель получает исправленный ref. Обходы оставлены бы у нескольких владельцев и не защищали бы остальных |
| X-04 | Выпустить релизный ref поверх известных дефектов R2–R7 | Запрещено решением архитектора: сначала зелёные CI + staging-gate на исправлениях, потом ref (`v1.7.4` = merge-коммит исправлений) |
| X-05 | Таблицу покрытия коммитить тем же токеном, которым её сгенерировали | Привело к красному `coverage-drift`: строка зависела от читателя. Организационный читатель в CI видит меньше, чем личный токен владельца |
| X-06 | Один общий skip или `continue-on-error`, чтобы CI был зелёным | Недопустимо: пропуск обязательного чека делает гейт декоративным |
