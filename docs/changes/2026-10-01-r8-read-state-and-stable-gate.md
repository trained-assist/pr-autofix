# 2026-10-01 — R8: читаемость — состояние таблицы, а не свойство читателя

Вторая выжимка карточки: два дефекта, найденных при доведении R1 до потребителей. Оба — в
reusable-реализации, оба — про одно и то же: **таблица не имела способа сказать, что именно она
не смогла прочитать.**

## Дефект 1: два разных 404 давали одну строку

GitHub отвечает `404` и тогда, когда репозитория нет, и тогда, когда у читателя нет к нему доступа.
`liveSource` падал на запросе дерева, `scanRemote` ловил исключение и писал
`unreadable: GitHub API HTTP 404`. Из этой строки нельзя было понять, что делать:

- репозиторий не виден этому читателю → задача по выдаче доступа;
- репозиторий читаем, но на ветке по умолчанию нет коммита → задача по первому коммиту.

В таблице они были одним текстом, а работа у них противоположная. Хуже: строка зависела от того,
**каким** читателем сгенерировали таблицу. Коммит таблицы делали с личным токеном владельца
(видит всё), гейт в CI — с организационным `AUTOFIX_PAT` (видит не всё). Отсюда красный
`coverage-drift` на карточке, которая сама добавила инвентарь в репозиторий.

Проверено фактом, а не рассуждением: `trained-assist/trained-assist-checklist` при полном токене
читается и имеет дерево. Предыдущий диагноз «репозиторий пуст, дерева нет» был неверен — он снят
как ложный, а не переинтерпретирован.

## Дефект 2: волатильные счётчики внутри byte-exact гейта

Заметка живого скана содержала `files=841, workflows=8`. Это свойства **текущего коммита**, а не
покрытия репозитория: любой чужой коммит в любом из 25 репозиторов менял таблицу, и гейт
краснел бы постоянно — включая на собственной карточке инвентаря, которая добавляет файл в свой
же репозиторий. Гейт, который краснеет всегда, отключают; отключённый гейт хуже отсутствующего.

Структурные факты, на которые действительно реагирует ревьюер, уже были колонками
(`ci_present`, `staging_present`, `fix.fixer_present`, `context.entrypoints_present`) — счётчики
дублировали их числом и не добавляли сигнала.

## Что изменено

- `read_state` вместо булева `readable`: `read` (прочитано всё), `empty` (репозиторий читаем,
  дерева на ветке по умолчанию нет), `no_access` (этот читатель не видит репозиторий — остальные
  колонки неизвестны, а не ложны).
- Заметка живого скана больше не содержит счётчиков; остаётся ветка, факт усечения дерева и факт
  пустоты.
- `repo-coverage.stable.json` — артефакт, который сравнивает гейт. Строка `no_access` в нём
  сведена к `(repo, read_state)`: гейт по-прежнему падает, когда репозиторий стал видим или
  перестал быть видим (именно в этот момент таблицу надо перегенерировать), и не падает на
  содержимое, которое он никогда не мог прочитать.
- Construction tasks: `unreadable` → `no_access`, плюс отдельный вид для пустого репозитория
  («нет коммита — нечего покрывать», а не «выдайте доступ»).

## Границы

- Гейт не ослаблен: читаемые строки сравниваются целиком, включая заметки.
- Слепое пятно по-прежнему видно и по-прежнему является задачей; `--strict` по-прежнему даёт код 4.
- Организационному читателю (`AUTOFIX_PAT`) по-прежнему нужен доступ ко всем 25 репозиторам,
  чтобы таблица не содержала `no_access`. Это задача владельца доступа, не кода; пока она не
  решена, таблица честно показывает пятно, а гейт остаётся зелёным.
