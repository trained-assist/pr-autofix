# 2026-10-02 — Z01 (итерация 5): R1 — доставка инструмента больше не стирает каталог потребителя

Пятая выжимка Z01 (предыдущие: `2026-10-01-z01-inventory-dev-baseline.md`,
`2026-10-01-r8-read-state-and-stable-gate.md`, `2026-10-01-z01-archive-class-of-defects.md`,
`2026-10-02-z01-r1-r4-closed.md`, `2026-10-02-z01-r1-r2-supply-boundary-closed.md`).
Итерация 5 закрывает блокирующее замечание R1 итогового вердикта кросс-ревью итерации 4
(вердикт: trained-agent-architecture#27#issuecomment-5945775126, применение: #37, блокер:
pr-autofix#61).

## Хронология

1. Итерация 4 развела корни **после** материализации: `actions/checkout … path: pr-autofix`
   писал в корень потребителя, следующий шаг `mv` уносил дерево в `$RUNNER_TEMP`. Для чистого
   репозитория это выглядело безопасно, но потребитель, у которого в корне есть **свой**
   каталог `pr-autofix/`, терял его: `actions/checkout` (`prepareExistingDirectory` →
   `remove = true` → `rmRF` каждого элемента) чистит цель, у которой нет `.git`, а `git add -A`
   автофикса кладёт удаление в индекс фикса.
2. Воспроизведено дважды независимо, включая **настоящий** `actions/checkout@v4`
   (пин `11d5960a326750d5838078e36cf38b85af677262`) на фикстурных репозиториях: 6/6 сценариев
   (4 точки доставки × tracked / untracked / symlink), плюс отдельный эксперимент
   «checkout-only без mv».
3. **План чинил неверную посылку.** Комментарии во всех точках утверждали, что
   `actions/checkout` не умеет класть дерево вне `GITHUB_WORKSPACE`. Это неверно: на пине
   `input-helper.ts:42-52` строит путь относительно `GITHUB_WORKSPACE` и **отказывается** от
   чего-либо вне его («Repository path … is not under …»). Ошибка в комментарии и породила
   дефект.
4. Фикс (план `eb4ae9e0`, T1–T6) — доставка сразу в `$RUNNER_TEMP`, без переноса:
   - проверка коллизии **до любой записи**: цель вне дерева потребителя; символьная ссылка или
     каталог без `.git` (не наш checkout) — громкий отказ, ничего не записано;
   - `actions/checkout` с абсолютным `path: ${{ runner.temp }}/pr-autofix` и переменной
     `GITHUB_WORKSPACE: ${{ runner.temp }}`, ограниченной этим шагом (раннер подставляет `env:`
     шага последним — `Runner.Sdk/ProcessInvoker.cs:262-275`, принудительно восстанавливаются
     только `GITHUB_ACTIONS`/`CI`). Абсолютный путь — страховка: без строки с переменной
     checkout откажется громко, а не попадёт в корень потребителя;
   - шаг «перенести дерево из корня потребителя» удалён во всех четырёх точках — это был
     второй разрушающий механизм.
5. Регрессии переписаны, а не подогнаны:
   - `r1-consumer-collision-probe` — исполняет поставляемые шаги против настоящего пинна
     checkout; окно доставки начинается с проверки коллизии, шаг checkout получает свой `env:`
     так же, как это делает раннер; добавлены четыре негативных случая проверки (ссылка,
     посторонний каталог, цель внутри дерева потребителя, прошлый клон инструмента);
   - `r1-root-separation-probe` — `${{ runner.temp }}` стал per-run значением (раньше путь
     рендерился в `/pr-autofix`, то есть проверялась форма, которую никто не поставляет), а
     фикстура потребителя **владеет** каталогом `pr-autofix/consumer-owned.md` — пустая фикстура
     делала все проверки сохранности вакуумными, и именно эта вакуумность пропустила дефект
     через два ревью; сценарий `e` проверяет контракт формы во всех четырёх точках;
   - `r1-shipped-run-step-probe` — эмуляция checkout уважает `GITHUB_WORKSPACE` шага,
     отказывает по containment и **чистит** цель без `.git`, вместо копирования поверх;
   - `r1-delivery-boundary-scan` — новый классовый инвариант: путь под `${{ runner.temp }}`,
     ограниченная переменная, проверка коллизии до записи, никакого переноса.
6. Негативные прогоны (регрессия формы в копии репозитория: `path: pr-autofix`, без `env:`):
   скан — `GAPS FOUND`; `r1-root-separation-probe` — 36/43, причём файл потребителя
   `pr-autofix/consumer-owned.md` уничтожен, а его удаление оказывается в индексе; проба с
   настоящим checkout — `DEFECT` 3/6.
